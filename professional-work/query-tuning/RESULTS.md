# Benchmark results

_Generated by `python -m tunekit run` on 1,000,000 appointments / ~2,500,000 events · SQLite 3.45.1 · Python 3.13.16 · median of repeated runs._

| Case | Before | After | Speed-up | Same result |
|---|---:|---:|---:|---|
| [Function on an indexed column](#sargable_dates) | 256 ms | 2.0 ms | 125.7× | yes |
| [Latest status per appointment: the index beats the rewrite](#latest_status) | 332 ms | 132.3 ms | 2.5× | yes |
| [One scalar subquery per column → one GROUP BY](#conditional_aggregation) | 437 ms | 47.9 ms | 9.1× | yes |
| [Join fan-out double counts → semi-join (EXISTS)](#fan_out_join) | 1,515 ms | 981.8 ms | 1.5× | **no - old query overstated by 87%** |
| [Join without a useful index → covering composite index](#covering_join) | 62 ms | 15.0 ms | 4.2× | yes |

## Function on an indexed column
<a id="sargable_dates"></a>

Wrapping a column in a function hides it from the index's ordering, so all 1M entries are read (plan: SCAN). A range on the raw column uses the index, and because the index also holds `units`, the table is never touched (covering index).

**Before**
```sql
SELECT COUNT(*) AS appointments, SUM(units) AS units
FROM appointments
WHERE STRFTIME('%Y-%m', booked_ts) = '2025-03'
```
Plan: `SCAN appointments USING COVERING INDEX ix_appts_ts_units`

**After**
```sql
SELECT COUNT(*) AS appointments, SUM(units) AS units
FROM appointments
WHERE booked_ts >= '2025-03-01' AND booked_ts < '2025-04-01'
```
Plan: `SEARCH appointments USING COVERING INDEX ix_appts_ts_units (booked_ts>? AND booked_ts<?)`

## Latest status per appointment: the index beats the rewrite
<a id="latest_status"></a>

With only the foreign-key index, each of ~100k correlated lookups fetches every event row and sorts them. A composite index in (appointment_id, event_ts, event_id) order that also carries `status` answers the same query straight from the index, already sorted. The 'obvious' rewrite to a window function was measured too: in this engine it was slower than the indexed correlated query. Measure, don't assume.

**Before**
```sql
SELECT b.session_id,
       SUM(CASE WHEN (SELECT e.status FROM appointment_events AS e
                      WHERE e.appointment_id = b.appointment_id
                      ORDER BY e.event_ts DESC, e.event_id DESC LIMIT 1) = 'CANCELLED'
                THEN 1 ELSE 0 END) AS cancelled_appointments
FROM appointments AS b
WHERE b.session_id < 200
GROUP BY b.session_id
```
Plan: `SEARCH b USING COVERING INDEX ix_appts_sess (session_id<?)` → `CORRELATED SCALAR SUBQUERY 1` → `SEARCH e USING INDEX ix_events_appt (appointment_id=?)` → `USE TEMP B-TREE FOR ORDER BY`

**After** (adds `ix_events_appt_ts`)
```sql
SELECT b.session_id,
       SUM(CASE WHEN (SELECT e.status FROM appointment_events AS e
                      WHERE e.appointment_id = b.appointment_id
                      ORDER BY e.event_ts DESC, e.event_id DESC LIMIT 1) = 'CANCELLED'
                THEN 1 ELSE 0 END) AS cancelled_appointments
FROM appointments AS b
WHERE b.session_id < 200
GROUP BY b.session_id
```
Plan: `SEARCH b USING COVERING INDEX ix_appts_sess (session_id<?)` → `CORRELATED SCALAR SUBQUERY 1` → `SEARCH e USING COVERING INDEX ix_events_appt_ts (appointment_id=?)`

```sql
CREATE INDEX ix_events_appt_ts ON appointment_events (appointment_id, event_ts, event_id, status);
```

Also measured: window-function rewrite (same indexes as fast): 494 ms (same result), slower than the indexed version.

## One scalar subquery per column → one GROUP BY
<a id="conditional_aggregation"></a>

Four subqueries mean four trips to the appointments table per session. A single join with conditional aggregation reads each appointment once, and a covering index means it never touches the table rows.

**Before**
```sql
SELECT d.session_id,
       (SELECT COALESCE(SUM(b.units), 0) FROM appointments AS b INNER JOIN referrers AS a ON a.referrer_id = b.referrer_id
         WHERE b.session_id = d.session_id AND a.channel = 'ONLINE')  AS online_units,
       (SELECT COALESCE(SUM(b.units), 0) FROM appointments AS b INNER JOIN referrers AS a ON a.referrer_id = b.referrer_id
         WHERE b.session_id = d.session_id AND a.channel = 'PHONE')  AS phone_units,
       (SELECT COALESCE(SUM(b.units), 0) FROM appointments AS b INNER JOIN referrers AS a ON a.referrer_id = b.referrer_id
         WHERE b.session_id = d.session_id AND a.channel = 'PARTNER') AS partner_units,
       (SELECT COALESCE(SUM(b.units), 0) FROM appointments AS b
         WHERE b.session_id = d.session_id AND b.referrer_id IS NULL)    AS direct_units
FROM sessions AS d
WHERE d.region = 'north'
```
Plan: `SCAN d` → `CORRELATED SCALAR SUBQUERY 1` → `SEARCH b USING INDEX ix_appts_sess (session_id=?)` → `BLOOM FILTER ON a (referrer_id=?)` → `SEARCH a USING INTEGER PRIMARY KEY (rowid=?)` → `CORRELATED SCALAR SUBQUERY 2` → `SEARCH b USING INDEX ix_appts_sess (session_id=?)` → `BLOOM FILTER ON a (referrer_id=?)` → `SEARCH a USING INTEGER PRIMARY KEY (rowid=?)` → `CORRELATED SCALAR SUBQUERY 3` → `SEARCH b USING INDEX ix_appts_sess (session_id=?)` → `BLOOM FILTER ON a (referrer_id=?)` → `SEARCH a USING INTEGER PRIMARY KEY (rowid=?)` → `CORRELATED SCALAR SUBQUERY 4` → `SEARCH b USING INDEX ix_appts_sess (session_id=?)`

**After** (adds `ix_appts_sess_cover`)
```sql
SELECT d.session_id,
       COALESCE(SUM(CASE WHEN a.channel = 'ONLINE'  THEN b.units END), 0) AS online_units,
       COALESCE(SUM(CASE WHEN a.channel = 'PHONE'  THEN b.units END), 0) AS phone_units,
       COALESCE(SUM(CASE WHEN a.channel = 'PARTNER' THEN b.units END), 0) AS partner_units,
       COALESCE(SUM(CASE WHEN b.referrer_id IS NULL    THEN b.units END), 0) AS direct_units
FROM sessions AS d
LEFT JOIN appointments AS b ON b.session_id = d.session_id
LEFT JOIN referrers AS a ON a.referrer_id = b.referrer_id
WHERE d.region = 'north'
GROUP BY d.session_id
```
Plan: `SCAN d` → `SEARCH b USING COVERING INDEX ix_appts_sess_cover (session_id=?) LEFT-JOIN` → `SEARCH a USING INTEGER PRIMARY KEY (rowid=?) LEFT-JOIN`

```sql
CREATE INDEX ix_appts_sess_cover ON appointments (session_id, referrer_id, units);
```

## Join fan-out double counts → semi-join (EXISTS)
<a id="fan_out_join"></a>

An appointment rescheduled twice joins to two events and its charge is counted twice. The report was overstated. EXISTS asks the question that was meant (was it ever rescheduled?), counts each appointment once, and with an index on (appointment_id, status) it is also faster.

**Before**
```sql
SELECT d.region,
       ROUND(SUM(b.charge * b.units), 2) AS rescheduled_appointment_charges
FROM appointments AS b
INNER JOIN appointment_events AS e ON e.appointment_id = b.appointment_id
INNER JOIN sessions AS d ON d.session_id = b.session_id
WHERE e.status = 'RESCHEDULED'
GROUP BY d.region
```
Plan: `SCAN e` → `SEARCH b USING INTEGER PRIMARY KEY (rowid=?)` → `SEARCH d USING INTEGER PRIMARY KEY (rowid=?)` → `USE TEMP B-TREE FOR GROUP BY`

**After** (adds `ix_events_appt_status`)
```sql
SELECT d.region,
       ROUND(SUM(b.charge * b.units), 2) AS rescheduled_appointment_charges
FROM appointments AS b
INNER JOIN sessions AS d ON d.session_id = b.session_id
WHERE EXISTS (SELECT 1 FROM appointment_events AS e WHERE e.appointment_id = b.appointment_id AND e.status = 'RESCHEDULED')
GROUP BY d.region
```
Plan: `SCAN b` → `CORRELATED SCALAR SUBQUERY 1` → `SEARCH e USING COVERING INDEX ix_events_appt_status (appointment_id=? AND status=?)` → `SEARCH d USING INTEGER PRIMARY KEY (rowid=?)` → `USE TEMP B-TREE FOR GROUP BY`

```sql
CREATE INDEX ix_events_appt_status ON appointment_events (appointment_id, status);
```

## Join without a useful index → covering composite index
<a id="covering_join"></a>

Same SQL, different physical design. Without an index on the join key the engine scans all 1M appointments and throws most away (plan: SCAN b + BLOOM FILTER). An index on the date filter plus a composite index on the join key that also carries the columns the query reads turns it into a few small index range scans.

**Before**
```sql
SELECT b.referrer_id,
       COUNT(*) AS appointments,
       ROUND(SUM(b.charge * b.units), 2) AS charges
FROM sessions AS d
INNER JOIN appointments AS b ON b.session_id = d.session_id
WHERE d.session_date BETWEEN '2025-06-01' AND '2025-06-30'
GROUP BY b.referrer_id
```
Plan: `SCAN b` → `BLOOM FILTER ON d (session_id=?)` → `SEARCH d USING INTEGER PRIMARY KEY (rowid=?)` → `USE TEMP B-TREE FOR GROUP BY`

**After** (adds `ix_sessions_date`, `ix_appts_sess_ref_cover`)
```sql
SELECT b.referrer_id,
       COUNT(*) AS appointments,
       ROUND(SUM(b.charge * b.units), 2) AS charges
FROM sessions AS d
INNER JOIN appointments AS b ON b.session_id = d.session_id
WHERE d.session_date BETWEEN '2025-06-01' AND '2025-06-30'
GROUP BY b.referrer_id
```
Plan: `SEARCH d USING COVERING INDEX ix_sessions_date (session_date>? AND session_date<?)` → `SEARCH b USING COVERING INDEX ix_appts_sess_ref_cover (session_id=?)` → `USE TEMP B-TREE FOR GROUP BY`

```sql
CREATE INDEX ix_sessions_date ON sessions (session_date);
CREATE INDEX ix_appts_sess_ref_cover ON appointments (session_id, referrer_id, charge, units);
```
