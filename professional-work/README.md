## How each project is laid out
```
project-name/
├── README.md         ← the problem, the approach, design decisions, how to run it
├── src/<package>/    ← the Python package doing the real work (each has a `python -m <package>` command)
├── tests/            ← the rules it must always satisfy, often checked against problems planted in the data
├── figures/          ← charts used in the README, generated by the code
└── ...               ← where useful: sql/, notebooks/, models/, sample_output/, config.yaml
```

To run any project: `cd` into it, `pip install -r requirements.txt`, then follow its **Run it** section. Every project is
self-contained.

**About the data:** everything is generated by code in each project. The clinic network and the farm co-op are
fictional settings chosen to show the methods; no employer data, code, names or figures are used, and every number in
these write-ups comes from synthetic data.
